# 동상이몽 MVP v2 실행 계획

기준: 2026-09-28 사용자 승인(면밀한 계획과 단계별 개발 시작). 입력은 조원의 MVP 수정 건의안과 기존 구현이다. 제안서의 모든 기능이 구현 완료된 것은 아니다.

## 제품 기준

회의 시작 → 기록 → 원문에 근거한 뜻의 차이 확인 → 참가자의 해석·조건 정리 → 결정과 다음 행동. 의견의 다양성을 오류로 평가하지 않는다. 숫자 지수뿐 아니라 근거 없는 낮음/보통/높음 등급도 도입하지 않는다. 정리됨과 합의됨을 구분한다.

## 이번 단계의 경계

기존 화면은 유지하고 /v2에서 첫 단계를 시연한다. 기존 /new·프로젝트 생성 API를 강제로 바꾸지 않는다. 기존 분석·음성 업로드·실시간 화면을 재사용한다. TXT·MD는 UTF-8 텍스트로 받으며 원문을 반드시 미리 확인한다. 자막·복잡한 대본 자동 구조화는 후속 단계다.

현재 SQLite 저장을 유지하고 실제 저장 위치를 표시한다. 사용자가 지정한 프로젝트 폴더로 저장 구조를 바꾸지는 않는다. 폴더별 데이터 이동은 2단계 전 별도 설계: DB를 정본으로 할지, 프로젝트마다 독립 저장할지 하나로 결정하고 내보내기와 실제 저장 위치를 혼동하지 않는다.

프로젝트 내 새 회의는 이전 원문·결정 맥락을 자동으로 가져오지 않는다. 기존 회의의 과거 결정 검사 동작은 유지한다. 회의별 참석자와 프로젝트 인물 연결은 2단계에서 정리한다. 이번 단계는 화자명을 입력 자료의 라벨로 취급하며 실명 식별을 주장하지 않는다.

가상·예정 대본의 실제 결정 승인과 결정 원장 반영은 서버에서 차단한다. 자료 유형을 화면과 분석 맥락에 표시한다. 저장은 AI 호출과 분리하며 실패한 분석은 저장한 회의에서 다시 시도한다.

## 검증 및 배포

합성 데이터로 API·SQLite 통합 테스트: 유효성 실패 무쓰기, 저장 왕복, 미확인 화자, 원문 보존, 타임스탬프, 기존 프로젝트 보존, 모의 자료 승인 차단. 브라우저로 준비 → 미리보기 → 저장 → 새로고침을 확인한다. 타입 검사·기존 전체 테스트·빌드로 회귀를 확인한다. 외부 모델을 실제로 호출하지 않은 검증은 합성/로컬이라고 명시한다.

개발 기준점: 로컬 278c99e. 별도 work/mvp-v2-intake-20260928 브랜치. 기존 DB에 대한 파괴적 변경 없음. 검증은 별도 임시 DB에서 진행. GitHub에는 검증 후 공개 범위로 선별해 PR을 준비하며 로컬 원문 이력을 통째로 push하지 않는다.

## 다음 단계에서 먼저 해결할 의사결정

- 로컬 전용과 외부 팀 공유 중 다음 배포 목표 선택.
- 프로젝트 폴더 저장의 정본·내보내기 정책과 기존 데이터 이동 방법.
- 회의별 참석 범위 및 사람의 확인을 누가 기록하는지.
- 분석 누락과 과잉 해석을 실제 자료로 평가할 기준과 팀 검토 절차.

위 결정은 이번 입력 단계의 구현을 막지 않는다. 기간·정확도·지연 수치는 측정 전 약속하지 않는다.

## 2026-09-28 추가 구현: 실제 처리 연결

사용자 요청 “실제 되도록”에 따라 2·3단계의 핵심 연결을 앞당겼다. v2 안에서 마이크 입력, 녹음 업로드, 실제 AI 분석, 원문 근거를 동반한 해석 확인 카드까지 이어진다. 녹음 중 후보 확인은 같은 페이지에 열어 녹음 컴포넌트를 유지한다. 분석 후보는 사람이 확인한 해석·동의로 자동 승격하지 않는다.

실제 API를 호출한 합성 음성·가상 마이크 검증을 완료했다. 이는 실제 다인 회의의 화자 구분·탐지 정확도 검증과 다르다. SRT/VTT, 전사 수정 버전, 요약/리포트 별도 주기, 종료 스냅샷과 재개, 참가자 본인 인증, 외부 v2 배포는 이 연결 작업으로 완료된 것이 아니다. 근거와 실행 결과는 `docs/MVP_V2_LIVE_VERIFICATION_20260928.md`를 참조한다.

## 검토 결함 수정 반영

분석 작업 회수, 녹음 중 범위 고정 수동 분석, 녹음 유지 동선, 화자 상태·발언 수정 및 이전 분석 경고, 종료 시각과 후처리 상태 분리를 구현했다. [수정 검증](MVP_V2_FIXES_20260928.md)에 실제 API 시험과 합성 회귀 시험을 구분해 기록했다. 전사 수정은 발언 단위 변경 이력과 재분석 표시까지이며, 가져온 파일 전체 버전 관리·발언 분할/병합 UI·종료 후 새 구간 재개는 아직 별도 작업이다.

실시간 후보에도 분석 당시 원문·화자 스냅샷 검사를 적용했다. 녹음 합치기 실패와 마지막 구간 분석 실패는 종료 완료로 처리하지 않으며, 마이크를 다시 켜지 않고 후처리를 재시도한다. [추가 수정 검증](MVP_V2_FOLLOWUP_FIXES_20260928.md) 참조.

## 팀 운영 연결 반영

진행자 인증을 적용하는 팀 모드, 참가자별 만료·회수 가능한 응답 링크, 본인 범위 응답 API, 녹음 구간 재개와 종료 스냅샷, DB 백업·복원 검증을 추가했다. 외부 운영 서버 정보와 도메인이 아직 없어 실제 외부 배포는 하지 않았다. 설치 구성과 범위는 [팀 운영 가이드](TEAM_OPERATIONS.md)에 정리했다. 실제 사람의 다인 장시간 품질 평가는 합성 API 검증으로 대체하지 않는다.
