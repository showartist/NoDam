# SceneNote MVP 개발 계획 — 2026-09-13

## 제품 목표와 범위
회의 목적과 원문을 기준으로 참가자 사이의 해석 차이와 지속적인 주제 이탈을 드러내고, 중립적인 확인 질문과 공동 결정 기록으로 연결한다. B안(근거 없는 0–100 점수 제거)을 유지한다. 사람의 성격·태도·권력을 AI가 평가하지 않는다.

현재 실행 방식은 로컬 앱 + OpenRouter Grok STT/Claude 분석이다. Astra 전사 엔진, 오프라인 LLM, 캐릭터 일관성 보장은 구현된 것으로 적지 않는다. 팀 스킬·Obsidian 아침 자동화는 별도 프로젝트 범위다.

## 이번 구현
1. 실시간 AI 후보 또는 직접 선택한 원문을 확인 안건으로 등록한다. 같은 후보 중복 등록과 타 회의 원문 참조를 막는다.
2. 참가자 이름·역할을 사람이 등록하고, 원문 / 각자의 이해 / 결정안을 3열로 비교한다.
3. 제안별로 동의·이견·확인 필요와 이해 내용을 기록한다. 응답은 진행자 입력이며 본인 인증된 투표가 아님을 표시한다. 침묵·미응답은 동의로 처리하지 않는다.
4. 제안 수정 시 기존 확인을 무효화한다. 현재 참가자 전원의 해당 제안에 대한 동의 기록이 있을 때만 공동 확인 완료로 전환한다. 확정 이후 본문 수정은 차단한다.
5. 실행 담당자·기한(미정 허용)·완료 기준을 결정에 연결하고, 완료 처리는 확인된 결정에만 허용한다.
6. AI 후보의 유효/오경보/판단 유보와 근거를 사람이 남겨 평가용 JSON으로 내보낸다. 평가 기록 개수를 모델 정확도로 표시하지 않는다.
7. 모든 변경에 revision 검사를 적용하고 이력을 저장한다. 새로고침 후 복원한다.

## 합격 기준
- 존재하지 않거나 다른 회의의 근거는 저장 불가.
- 같은 AI 검토 후보는 안건 한 개로 유지.
- 참가자 0명, 미응답, 이견, 확인 필요, 제안 수정 후 과거 동의로 확정 불가.
- 동시 편집의 오래된 revision은 409. 확인 완료 내용은 변경 불가.
- 담당자와 완료 기준이 없는 상태에서 확인 완료 불가. 타 회의 참가자를 담당자로 지정 불가.
- 진행자가 기록한 동의임을 UI/내보내기에서 명시. 자동 합의 주장 불가.
- 브라우저에서 안건 생성→제안→응답→차단→전원 동의→확인 완료→실행 완료→새로고침 복원 확인.
- 기존 296 tests / 283 pass / 13 skip / 0 fail 기준선보다 통과 수 감소 없음. 타입·빌드 성공.

## 후속 단계
- 외부 실시간 공유: 전용 키 설정은 기존 자동 승인 거부로 대기. 승인 후 실제 외부 전송·갱신·종료 검사. 이번 계획 요청을 비밀키 설정의 별도 승인으로 간주하지 않는다.
- 현장 품질: 실제 3인 이상 한국어 회의의 화자·이름·전사·알림 시점, 30분 이상 연속 처리 및 중단 복구 측정.
- 정답 자료: 팀이 원문에 주제 이탈/사례/본론 복귀/해석 차이를 표시하고 오경보·누락을 평가. 초기 90초·중복 억제 기준을 실제 데이터로 조정.
- 회의 요약의 10월 3일 일정은 2024년 표기와 충돌하므로 연도 미확정. 담당자는 실명과 수락 여부 확인 전 자동 배정하지 않는다. 캘린더/Slack/카카오톡 발송 없음.
