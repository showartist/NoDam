## 수정과 합격 기준

| 검토 항목 | 근본 원인 | 변경·검증 |
|---|---|---|
| 중단된 전체 분석이 계속 처리 중 | DB running 행의 생존 확인·회수 없음 | 10초마다 실행 신호 갱신, 45초 만료 시 화면/요청에서 실패로 회수. 이전 버전의 실행 신호 없는 행은 10분 경과 기준. 살아 있는 작업 중복 실행 차단, 만료된 실행자의 결과 저장 차단 테스트 통과 |
| 녹음 중 수동 체크 불가 | 서버가 활성 녹음을 일괄 거절 | 요청 시점의 발언 복사본·마지막 발언 ID·개수를 저장하여 분석. 후속 발언은 해당 분석에 포함하지 않음. 실제 녹음·전사와 분석 동시 실행 검증 |
| 화자 구분 상태 표시 부족 | v2가 전사 결과의 화자 구분 상태를 읽지 않음 | 미확인 경고와 사람의 발언·화자 수정 화면 추가. 원래 text_raw와 수정 전후 이력 보존. 새 분석의 원문 복사본과 비교하여 오래됨 표시. 이전 버전 분석도 수정 이후 재확인 필요 처리 |
| 뜻 확인 버튼이 녹음을 끊을 수 있음 | 일부 버튼·링크가 다른 페이지로 이동 | 일반 결정 기록·실시간 후보·수동 분석 후보 모두 라이브 화면 안에서 열기. 녹음 중 다른 페이지 링크 차단, 문서 새로고침/닫기 beforeunload 확인. 실제 가상 마이크에서 일반 버튼·링크 검증 |
| 종료와 후처리 혼동 | 모든 전사·분석 후에 종료 시각·화면 반영 | 후처리 완료 전에 종료 시각을 한 번 저장, UI에 녹음 종료/전사·분석 처리 중 분리 표시. 프로세스 중단 후 종료 처리 재시도, 후처리 예외 복구, 중복 종료 요청 테스트 통과 |

실행 신호는 로컬 작업 생존 확인이며 외부 공급자의 과금 취소·요청 취소를 보장하지 않는다. 중단된 분석 재시도는 새 API 요청이다. 녹음 종료 시각은 종료 처리 요청을 서버가 수락한 시각이며 전사·분석 완료까지 지연시키지 않는다.

발언 수정은 녹음 및 종료 처리 후 허용한다. 원래 발언과 수정 전후 값은 보존하며 분석용 발언만 바꾼다. 화자 이름은 사용자의 수정 기록이고 생체 음성 식별 결과가 아니다. 다른 수정이 먼저 저장됐으면 409로 거절한다. 화자만 바뀌어도 이전 분석 후보를 가져오거나 그 후보에서 결정을 확정하지 못하도록 한다.

## 남아 있는 범위

이번 수정은 검토의 우선 결함 5개와 발언·화자 수동 수정 연결이다. 실제 다인 장시간 회의 품질 평가, 자동 음성 프로필·실명 식별, 종료한 같은 회의의 새 구간 재개·결과 스냅샷, 선택적 후속 맥락, SRT/VTT, 요약3분/리포트15분 분리, 프로젝트 폴더 지정, 외부 인증·공유 배포, v2 통합 유틸리티는 별도 작업이다.

종료 처리는 현재 HTTP 요청과 저장 상태·명시적 재시도로 복구한다. 별도 상시 작업 서버를 구축한 것은 아니다. 이전 ‘종료한 회의 계속하기’와 이번 ‘중단된 종료 처리 재시도’는 다른 기능이다. 물리적 마이크·브라우저별 절전·닫기·뒤로가기 전체 조합은 미검증이다.
