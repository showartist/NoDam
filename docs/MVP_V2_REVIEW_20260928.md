## 검토에서 확인한 우선 보완점

### 1. 중단된 전체 분석이 영구 처리 중으로 남을 수 있음 — 높음

- 원인: `app/api/meetings/[id]/analyze-v2/route.ts:21`은 실행 중 행이 하나라도 있으면 409를 반환한다. `lib/alignment/analyze.ts:197`의 실패 처리는 살아 있는 프로세스의 catch에서만 실행된다. 비정상 종료 뒤 만료·회수 처리가 없다.
- 화면도 `app/v2/m/[id]/MeetingActions.tsx:12`에서 실행 중이면 분석 버튼을 비활성화한다.
- 별도 임시 DB에 오래된 running 행을 넣어 재시도를 재현했다. 실제 서버를 강제 종료한 시험은 아니며, 프로세스 종료 후 남는 DB 상태를 모사했다.

```text
./node_modules/.bin/tsx /tmp/nodam-review-stale.ts
httpStatus: 409
error: 이미 전체 분석을 처리하고 있습니다. 저장된 결과를 새로고침해 주세요.
remainingStatus: running
providerCalls: 0
```

- 합격 기준: 종료된 프로세스의 작업과 살아 있는 작업을 구분하고, 중복 과금 없이 중단된 작업을 실패·재시도 가능 상태로 회수한다.

### 2. 화자 구분의 불확실성이 v2 결과에 충분히 표시되지 않음 — 높음

- `lib/transcription/long.ts:122`는 전체 화자 구분을 확정하지 못한 결과를 unsupported로 기록할 수 있다. 이번 실제 API 응답도 이 상태다.
- `app/v2/m/[id]/page.tsx:41`은 이름 또는 화자 ID를 표시하지만 전사 실행의 화자 구분 상태를 읽지 않는다. 사용자가 화자 번호를 확정된 사람으로 오해할 수 있다.
- 합격 기준: 화자 신뢰 상태를 표시하고, 잘못 합쳐지거나 나뉜 화자를 사람이 수정한 뒤 관련 분석을 다시 확인할 수 있어야 한다.

### 3. 녹음 중 수동 ‘동상이몽 체크’는 아직 지원하지 않음 — 기능 차이

- `app/api/meetings/[id]/analyze-v2/route.ts:19`은 녹음 중 요청을 409로 차단한다. 현재는 주기 분석을 보거나 녹음 종료 뒤 전체 분석을 실행한다.
- 건의안의 ‘현재까지 대화를 원할 때 체크’와 차이가 있다.
- 합격 기준: 녹음을 유지하면서 요청 순간의 발언 범위를 고정해 분석하고, 이후 들어온 발언과 구분한다.

### 4. 녹음 중 뜻 확인 동선이 일관되지 않음 — 중간

- 실시간 후보의 ‘함께 확인하기’는 같은 페이지에 열도록 연결했다.
- 하지만 `app/v2/m/[id]/page.tsx:31`의 일반 ‘함께 뜻 확인·결정 기록’ 링크는 다른 페이지로 이동한다. LiveBoard 언마운트 시 LiveCapture.dispose가 마이크를 정지한다.
- 합격 기준: 녹음 중 확인 동선 전체를 같은 페이지에서 처리하거나 녹음 유지 방식·명시적 중단 절차를 일관되게 제공한다.

### 5. 종료와 분석 완료가 아직 분리되지 않음 — 기능 차이

- `lib/live/session.ts:308`은 전사 큐를, 317줄은 남은 분석을 기다린 뒤 349줄에서 stopped를 기록한다.
- 건의안의 ‘회의 종료 후 결과 화면에서 처리 상태를 확인’ 흐름과 다르다.
- 합격 기준: 녹음 종료 시점을 먼저 고정하고, 전사·분석은 별도 상태로 이어가며 종료 시점 결과를 보존한다.
