# 공동 결정 MVP 구현·검증 — 2026-09-13

## 결과

[개발 계획](MVP_PLAN_20260913.md)의 이번 구현 1~7을 구현했다. 새 화면 `/m/[id]/decisions`는 실시간 검토와 같은 회의 원문을 사용한다. 모델 추가 호출 없이 사람이 각자의 이해를 기록하고 공동 확인과 실행 과제로 연결한다. 기존 B안은 유지했다.

- 실시간 후보의 ‘함께 확인하기’로 원문 근거를 가져오고 해당 안건을 선택한다. 같은 후보 재등록은 중복 생성하지 않는다.
- 참가자·역할 입력과 원문 / 각자의 이해 / 결정안·담당자·기한·완료 기준 3열 화면.
- 미응답·이견·확인 필요·담당자 없음은 공동 확인 완료를 차단한다. 제안 저장 시 과거 응답을 무효화한다.
- 제안 변경 시 응답 재확인, 원문이 바뀌었으면 과거 근거 확정 차단, 확인 완료 본문 수정 차단. 담당자·기한 변경도 제안 변경으로 처리한다.
- 새 참가자가 추가되면 미확정 안건에 그 사람의 응답이 필요하다. 이미 확인 완료된 결정은 당시 참가자 목록을 보존한다.
- 과제 완료는 공동 확인 완료 후에만 가능. 날짜 미정은 명시적으로 허용하고 자동으로 날짜/담당자를 만들지 않는다.
- 사람의 후보 평가(확인 필요/오경보/판단 유보)와 근거, 변경 기록을 저장한다. JSON 내보내기에는 최근 변경 100개를 포함하며 전체 이벤트는 DB에 보존한다.
- revision이 지난 수정은 409. 화면 입력은 서버 저장 중 잠기고, 저장 실패 시 다시 시도할 수 있다.

## 검증 명령과 실제 출력

로그·브라우저 실행 스크립트·스크린샷·내보낸 JSON은 `.data/verification/decisions-20260913/`에 있다. 민감한 원문을 이 문서나 Git에 복제하지 않았다.

```text
npx tsc --noEmit                                      exit 0
npx tsx --test tests/meeting_decisions_runtime.test.ts exit 0
  tests 13 / pass 13 / fail 0
npm test                                             exit 0
  각 Node 테스트 러너 합산 309 tests / 296 pass / 13 skip / 0 fail
npm run build                                        exit 0
```

기존 기준선 296/283/13/0에서 새 테스트 13개가 추가됐다. tsc.log, runtime.log, npm-test.log, build.log에 원출력을 보존했다. 공급자/현장 품질 검사를 추가 수행한 것으로 세지 않는다.

새 검사는 실제 라우트와 SQLite를 호출한다. 존재하지 않는 근거/다른 회의/임의 인용 차단, 참가자 없는 상태, 미응답·이견·유보, 제안 변경 시 재확인, 참가자 추가, 과제 상태 제한, 잘못된 날짜, 오래된 버전, 평가 저장, 원문 변경, AI 후보 중복/다른 회의, 이름 중복·cross-origin 요청 거부를 검사했다. 데이터와 AI 후보는 합성으로 주입했으며 외부 AI 호출은 하지 않았다.

브라우저 전체 흐름:

```text

{"meetingId":"decision-check-1789262865246","revision":11,"participants":2,"questions":1,"taskDone":true,"errors":[],"mobileOverflow":false}
```

참가자 등록 → 원문 안건 → 결정안 → A 동의/B 이견(완료 비활성) → 결정안 변경(동의 초기화) → A/B 재동의 → 공동 확인 완료 → 과제 완료 → 새로고침 복원 → JSON 다운로드를 실제 브라우저에서 검사했다. 초기 검사에서는 선택 상자의 접근성 이름, 저장 응답 대기, 모바일 메뉴 가로 넘침이 드러났고 보완 후 통과했다. 실패 로그도 보존했다.

```text

```

두 번째 검사에서는 합성 후보를 실시간 화면에 넣고 ‘함께 확인하기’ → 선택된 안건 → 고정 목적 → 유효성 평가 저장 → 새로고침 복원을 확인했다. 운영 AI 출력인 것처럼 기록하지 않았다.

## 사용과 남은 범위

로컬 앱 상단 ‘함께 결정’에서 시작한다. 실시간 후보에서도 ‘함께 확인하기’를 누를 수 있다. 검증용 예시는 `/m/decision-check-1789262865246/decisions`이며 참가자와 내용은 합성이다. 기존 실제 회의에는 임의 참가자·동의·확정 결정을 넣지 않았다.

**기록의 의미:** 진행자가 참가자의 확인 내용을 입력한다. 본인 인증된 전자투표나 법적 승인 시스템이 아니며, 권력관계·강요를 기술적으로 방지했다고 주장하지 않는다. 누가 어떤 뜻으로 동의했다고 기록했는지와 그 변경 이력을 드러내는 MVP다.

공유 서버용 비밀키 승인은 여전히 대기다. 새 페이지는 로컬에서 작동하며, 외부 읽기 앱에서 공동 결정 편집/본인 인증은 제공하지 않는다. 외부 실시간 연결, 실제 3인 이상 한국어 회의 정확도, 30분 이상 사람 음성 운영은 이전 보고서의 미완료 상태를 유지한다. 회의 날짜의 2024 표기 및 Speaker별 실명/수락 여부를 임의 확정하지 않았다.
