# 알려진 한계와 데모 경계

## 이 문서를 두는 이유

현재 화면에서 보이는 기능과 실제 백엔드·AI 연동 상태를 구분하기 위해 기록합니다. 제한사항은 실패 목록이 아니라, 팀이 다음 작업의 우선순위를 정하기 위한 기준입니다.

## 현재 한계

### 1. GitHub `main`만으로 통합 앱을 실행할 수 없음

현재 `main`에는 문서와 파트별 폴더 안내가 중심이며, 웹 애플리케이션 소스와 통합 실행 설정이 없습니다. 별도 프로토타입을 팀 저장소에 반영할 때 설치·실행·환경변수 문서가 함께 필요합니다.

### 2. STT와 화자 분리가 실제 스트림에 연결되지 않음

현재 UX는 전사 데이터 표시와 연결 지점을 검토하는 수준입니다. 마이크 입력, 지연 시간, 화자 오인식, 중간 결과 수정 전략을 검증해야 합니다.

### 3. 분석 결과가 운영 LLM 호출로 검증되지 않음

결정론적 규칙과 fixture로 구조를 시험했으며, 슬라이딩 윈도우 LLM의 정확도·비용·지연·재시도 정책은 미확정입니다.

### 4. 동상이몽 지수는 연구·검증이 필요함

점수 산식과 임계치가 실제 제작 회의에서 유효한지 검증되지 않았습니다. 점수만 보여주지 말고 근거 발화와 사용자 확인을 함께 제공해야 합니다.

### 5. 이미지는 발표용 사전 생성 자료임

현재 이미지 흐름은 발표용 사전 생성 이미지와 fixture를 표시하는 방식입니다. 다중 레퍼런스 비중을 반영한 실시간 생성, 저작권, 생성 실패, 비용 정책은 별도 구현이 필요합니다.

### 6. 오프라인 폴백은 실제 기능을 대체하지 않음

통신 오류 시 오프라인 fixture로 데모를 이어갈 수 있지만, 실제 API 성공으로 기록하거나 표시하면 안 됩니다. UI와 로그에서 `fixture`와 `live`를 구분해야 합니다.

### 7. 회의 버전 관리와 RAG가 없음

여러 회의에 걸친 설정 변경, 과거 결정 검색, 모순 감지는 목표 기능이며 현재 `main`에 구현되어 있지 않습니다.

### 8. 보안·개인정보 정책이 미확정

음성, 얼굴·캐릭터 설명, 회의 내용에는 민감정보가 포함될 수 있습니다. 저장 기간, 접근 권한, 삭제, 외부 AI 전송 동의가 필요합니다.

## 발표에서 사용할 표현

> 2026-08-22 갱신: STT 와 동상이몽 분석이 실제 API 호출로 바뀌면서 아래 표의 일부 행을 고쳤습니다.

| 피해야 할 표현 | 권장 표현 |
| --- | --- |
| 실시간 STT 음성 전사 | 업로드한 녹음 파일을 OpenRouter STT 로 전사 (실시간 마이크 입력은 미구현) |
| AI 가 화자를 정확히 구분 | 화자분리를 요청하고 결과를 받지만 한국어 정확도는 미검증 |
| 슬라이딩 윈도우 LLM으로 추출 | 회의 전사 전체를 LLM 에 넘겨 해석 차이를 추출 |
| 화면이 절대 멈추지 않음 | 외부 API 실패 시 오류를 그대로 표시 (fixture 자동 대체 없음) |
| 현재 뼈대 완결 | 음성 → 전사 → 분석 구간이 동작하며 이미지 생성·실시간 입력은 미구현 |
| 고화질 이미지 자동 전환 | 발표용 사전 생성 이미지 표시 |
| 동상이몽 지수를 계산 | 미해결 이슈 수 기반 점수 (해석 거리 지표 아님) |
