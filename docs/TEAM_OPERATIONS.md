# 동상이몽 — 한 팀 운영 가이드

기준: 2026-09-28, 단일 Node 서버·영속 디스크 운영. v2를 실제 회의 운영 흐름으로 연결한 버전이다. 외부 서버에 배포됐다는 의미는 아니다.

## 구현된 사용 흐름

1. 진행자가 로그인하고 프로젝트·회의 목적을 만든다.
2. 마이크로 기록한다. 20초 조각마다 실제 전사를 요청하고 설정한 3·5·10분 구간을 검토한다. 전사와 모델 응답 시간이 추가된다.
3. AI 후보를 원문과 대조하고 확인 안건으로 가져온다. 다른 해석을 잘못된 의견으로 단정하지 않는다.
4. 참가자 이름을 등록하고 ‘개인 응답 링크’를 각 사람에게 따로 전달한다.
5. 참가자는 자기 링크에서 자신의 해석·조건·진행 동의/반대/보류를 기록한다. 진행자는 최신 기록을 불러와 확인한다.
6. 반대·미응답·미해결 해석이 남으면 공동 확인 완료로 기록할 수 없다. 참가자 직접 응답과 진행자 대리 기록은 구분된다.
7. 녹음을 종료하면 해당 시점의 누적 발언과 결정 기록을 JSON으로 보존한다. ‘같은 회의 이어서 녹음’은 새 구간을 만들며 이전 스냅샷을 바꾸지 않는다. 여러 구간을 마지막 구간의 음성으로 덮어쓰는 재전사는 차단한다.

개인 링크는 암호학적으로 무작위 생성되고 DB에는 해시만 남는다. 7일 후 만료되며 재발급·회수 시 이전 링크가 무효화된다. 링크 소지자가 해당 참가자로 응답하므로 링크를 재전달하지 않는다. 주민등록·사내 계정 등 실명 인증을 구현한 것은 아니다. 진행자는 회의 전체를 관리하는 단일 팀 관리자다. 여러 회사가 함께 쓰는 서비스의 조직별 권한은 별도 범위다.

## 외부 운영 설치

필요: 상시 실행 가능한 Linux 서버, 서버를 가리키는 도메인, Docker Compose, 80/443 포트. 이 환경 정보는 아직 제공되지 않았다. 이 Mac에는 Docker/Caddy 실행 도구가 없어 컨테이너 자체 실행은 미검증이다. Next 정식 빌드와 로컬 HTTPS 역방향 프록시의 실제 브라우저 인증·응답 검증을 수행했다.

```sh
node scripts/init-team.mjs meeting.example.com
```

`deploy/.env`와 `deploy/admin-credentials.txt`가 권한 600으로 생성된다. 기존 파일은 덮어쓰지 않는다. API 키는 운영자가 `.env`의 OPENROUTER_API_KEY에 직접 설정한다. 비밀번호나 키를 Git에 넣지 않는다.

```sh
docker compose -f deploy/compose.yaml up -d --build
```

진행자는 `https://설정한도메인/v2`에 접속해 계정 `admin`과 생성된 비밀번호로 로그인한다. 참가자는 개인 초대 링크만 사용한다. 앱 포트는 호스트에 공개하지 않고 HTTPS 프록시만 80/443을 연다. `.data`는 별도 영속 볼륨으로 보관하며 컨테이너 재생성 뒤에도 유지한다. 서버는 한 개만 실행한다. 프로세스 메모리의 녹음 큐를 사용하는 현재 구조로 여러 인스턴스를 동시에 띄우지 않는다.

관리 화면·원문·기존 API도 진행자 인증으로 보호한다. 공개 허용 경로는 `/join`, `/api/participation`, 정적 JS/CSS이며 참가자 API는 자체 Bearer 권한 검사를 수행한다. 운영 모드에서 인증 설정이 빠지면 503, 미인증 관리 요청은 401이다. `NODAM_PUBLIC_ORIGIN`을 실제 HTTPS 도메인과 일치시킨다.

참고: [Next.js 자체 호스팅](https://nextjs.org/docs/app/guides/self-hosting), [Caddy 자동 HTTPS](https://caddyserver.com/docs/automatic-https).

## 데이터 보존·복구

DB만 백업할 때:

```sh
node scripts/backup-meeting-db.mjs /안전한경로/meeting-backup.db
```

기본 DB 또는 SCENENOTE_DB의 SQLite 온라인 백업을 만들고 integrity_check를 수행한다. 새 경로만 허용한다. 회의 기록·초대 해시·결정·스냅샷이 포함된다. 음성 파일은 DB에 들어 있지 않으므로 DB 백업만으로 녹음까지 복구된다고 보지 않는다.

서버 전체 백업은 회의를 종료하고 앱을 정지한 뒤 `.data` 영속 볼륨 전체를 별도 디스크에 보관한다. 복구 시 기존 데이터를 덮어쓰기 전에 별도 빈 저장소에 풀고, DB 무결성 및 회의별 음성 파일을 확인한다. `docker compose down -v`는 데이터를 지우므로 사용하지 않는다. 자동 예약 백업은 등록하지 않았다.

## 현장 사용 전 확인

- 운영 URL에서 진행자 로그인, 다른 브라우저에서 개인 초대 링크 응답을 확인한다.
- 실제 참가자들에게 녹음과 외부 전사·분석 전송을 알리고 마이크 입력을 확인한다.
- 화자 자동 구분과 해석 후보는 원문과 대조한다. 실제 다인 장시간 회의의 오탐·누락률을 측정해 합격시켰다는 주장은 하지 않는다.
- 회의를 끝내고 종료 기록을 내려받으며 백업을 별도 위치에 둔다.

## 검증 범위

합성 DB: 초대 만료·회수·해시 저장·타인/다른 회의 응답 차단·버전 충돌·관리 인증·재개 시 시간 경계·스냅샷 불변·DB 복원.
실제 브라우저: 로컬 HTTPS에서 진행자와 두 참가자의 독립 세션으로 해석 입력 → 반대 시 확정 차단 → 동의 후 확정 → 링크 회수 확인.
실제 API 시험은 별도 검증 기록에 합성 음성임을 명시한다. 외부 도메인·TLS 발급·운영 서버에서의 컨테이너 시작·실제 팀원 회의 검증은 서버 환경을 연결한 뒤 수행한다.
