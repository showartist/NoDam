## 7. 런타임 배선 및 최종 회귀

**근본 원인:** 기본 테스트의 배선 검사는 정적 코드 검색뿐이었다.

**변경/검증:** `npm run test:full`을 실제 실행했다. 기존 30개 정적 검사와 9개 서버 렌더 검사, 5개 코드 변이 검출에 더해 업로드 라우트→스트리밍→Opus→공급자 경계→DB 테스트를 추가했다. 공급자 정적 검사는 이동한 실제 호출 경로까지 검사하도록 바꿨으며 삭제하지 않았다. 별도 `verify-review-ui.ts`는 이미 분석한 회의에 대해 실제 API 집계와 렌더된 요약을 대조한다. 마이크 복구는 위의 실제 브라우저 검증으로 구분해 기록했다.

수정 전 재실행 기준선은 사용자 제시 수치보다 1개 많은 **270 tests / 257 pass / 13 skip / 0 fail**이었다(기존 경계 테스트 포함). 수정 후 **281 tests / 268 pass / 13 skip / 0 fail**, 핵심 **23 pass**다. 기존 테스트의 통과 수는 줄지 않았다. `test:full`의 추가 라우트 테스트는 별도 1 pass이며 변이 5건 모두 검출했다.

검증 환경: 로컬 Node/ffmpeg, 외부 Neon DB 테스트는 기존처럼 13개 skip. 검증 명령에서는 `DATABASE_URL`을 제거하고 `SCENENOTE_DB=/tmp/nodam-review-final/test.db`로 격리했다. 외부 DB 통합 검증 성공으로 쓰지 않는다.

```text
npx tsc --noEmit --incremental false                   exit 0
npm test                                              exit 0 (281 / 268 pass / 13 skip / 0 fail)
npm run test:full                                     exit 0 (정적+서버 렌더+변이+라우트)
npm run build                                         exit 0
npx tsx --test tests/capstone_core.test.ts tests/capstone_audio.test.ts
                                                      exit 0 (23 pass / 0 fail)
```

각 명령의 원출력은 [검증 폴더](verification/review-20260912/)와 `results.json`에 보존했다. `test:spec`의 예상 실패를 성공 근거로 사용하지 않았다.
