# 해석 비교 카드 구현·검증 — 2026-09-13

## 근본 원인과 목표
기존 공동 결정은 원문과 최종 이해·진행 동의는 기록했지만, 결정 전 참가자마다 다른 뜻·예시·실행 조건을 비교하고 공통 조건으로 정리하는 단계가 없었다. 사용자의 ‘서로 다른 뜻으로 이해하는 상황을 풀어주는 프로그램’ 개발 지시에 따라 기존 확인 안건에 해석 비교 카드를 추가했다.

## 변경한 동작
1. 기존 AI 확인 후보 또는 직접 등록한 원문 안건에서 비교할 표현과 구체적인 결정 대상을 입력한다. 표현은 해당 안건의 원문 근거에 실제로 존재해야 한다.
2. 참가자별 뜻·구체적인 예·실행 조건을 나란히 표시한다. 본인 확인을 명시해야 해석이 기록된다. 예시·조건이 비어 있으면 미확인으로 남기고 확인 질문을 표시한다.
3. 진행자가 확인한 해석의 관계를 ‘같은 뜻 / 서로 보완 / 선택이 필요한 차이 / 아직 미확인’으로 정리한다. 문구가 다르다는 이유만으로 자동 충돌 판정을 하지 않는다.
4. 함께 확인할 조건과 남은 차이·처리 방향을 기록한다. 조건을 결정안 초안으로 가져오고 담당자·기한·완료 기준과 함께 저장한 뒤 별도로 진행 동의를 받는다. 뜻이 모두 같을 필요는 없고, 기존 ‘우려를 남기고 진행 동의’를 사용할 수 있다.
5. 참가자의 해석 미확인, 정리 미완료, ‘아직 미확인’ 상태는 전원이 진행 동의를 입력해도 서버에서 확정을 막는다. 해석·정리·비교 대상 변경 및 새 참가자 추가 시 필요한 단계와 진행 동의를 다시 확인한다.
6. 확정된 해석·정리·응답은 변경할 수 없으며 당시 참가자와 함께 보존한다. 실행 과제와 JSON 내보내기에 함께 확인한 조건, 남은 차이와 우려를 표시한다. 비교 카드를 사용하지 않은 기존 결정의 데이터와 동작은 유지한다.

## 검증
전체 검사 결과: `npx tsc --noEmit` exit 0; `npm test` 320 tests / 307 pass / 13 skip / 0 fail, exit 0; `npm run build` exit 0. 이전 312 tests / 299 pass / 13 skip / 0 fail에서 8개 검사가 추가됐다.

추가한 8개 검사는 원문 표현 범위, 해석 미응답, 본인 확인 표시, 다른 회의 참가자 거부, 보완 관계의 확정·복원·스냅샷, 미확인 차단, 의견 차이 보존, 수정 시 재확인·이력, 새 참가자와 과거 확정 보호, 오래된 수정 거부를 확인한다. 이전 테스트를 삭제하거나 기대값을 완화하지 않았다.

브라우저는 합성 3인 회의에서 ‘따뜻함’을 관계·조명·공간으로 다르게 이해한 내용을 입력하고, 보완 관계로 정리하여 조건을 결정안에 가져오기 → 우려를 남긴 진행 동의 → 확정 → 새로고침 → JSON 다운로드까지 실제 Chrome으로 검증했다. 세 해석이 서로 다른 채 보존되고 모바일 가로 넘침·브라우저 오류가 없음을 확인했다.

## 범위와 한계
추가 AI 호출이나 새로운 의미 탐지 모델은 도입하지 않았다. 기존 실시간 AI 후보·원문 질문에서 시작해 사람이 해석을 확인하고 정리하는 단계다. 후보·분류를 자동으로 사실이나 합의로 바꾸지 않는다. 이번 데이터는 합성이며 실제 참가자 해석 확인이나 새 모델의 정확도 검증으로 세지 않는다. 본인 확인 표시는 진행자가 해당 참가자에게 확인했다고 기록하는 것으로, 본인 인증 기능이 아니다.

로컬 NoDam에 구현했다. 외부 팀원의 실시간 편집·본인 인증·외부 실시간 공유 연결은 이번 변경 범위에 포함되지 않는다. 0–100 동상이몽 점수는 부활시키지 않았다. 원본 회의 데이터는 변경하지 않았다.
