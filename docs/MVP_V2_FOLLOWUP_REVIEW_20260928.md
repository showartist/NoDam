## 재현된 결함

### 1. [P1] 실시간 후보는 화자 수정 후에도 이전 판단으로 확정 가능

근거: `lib/meetingDecisions/store.ts:54-78`, `:111-117`.
수동 분석 `import_analysis`와 `analysisSource`만 원문 변경 검사를 한다. 실시간 `import`는 인용 문자열 존재 여부만 검사하고 화자·발언 버전을 고정하지 않는다.

합성 재현: 서로 다른 화자의 ‘따뜻함’ 해석 차이 후보를 저장 → 두 번째 화자 이름을 첫 번째 사람과 같은 이름으로 수정 → 예전 실시간 후보 가져오기 → 사람이 결정안과 동의를 기록 → 확정 성공.

출력: `LIVE_STALE_SOURCE {"speakers":["민지","민지"],"oldMeaningGapImported":true,"confirmed":true,"blockers":[]}`

이는 AI가 혼자 합의를 만들었다는 뜻은 아니다. 사람의 후속 입력은 있었지만, 근거가 바뀐 AI 후보를 재검토 없이 사용했다는 결함이다. 앞선 ‘이전 분석 확정 차단’ 수정은 모든 경로에 적용된 것이 아니었다.

합격 기준: 실시간 검토에도 분석 당시 UID·내용·화자 버전을 저장한다. 화자만 수정한 경우에도 기존 후보에 재검토 표시를 하고 가져오기·확정을 막는다. 새로 추가된 발언만으로 기존 범위를 무효화하지 않는다. 이미 확정한 기록은 당시 스냅샷을 보존하면서 이후 변경 사실을 구분한다.

### 2. [P1] 전체 녹음 합치기 실패를 성공으로 반환

근거: `lib/live/session.ts:326-349`.
ffmpeg callback이 오류·종료코드를 무시하고 항상 resolve한다. 결과 파일이 없어도 full_audio 경로를 저장하고 stopped로 끝낸다. done 조각 중 파일이 사라진 경우도 filter(existsSync)로 조용히 제외한다.

합성 재현: done으로 저장된 조각 파일을 잘못된 WAV로 준비하고 종료. ffmpeg는 실패하지만 stopSession은 정상 반환했다.

실제 출력 요지: `fileExists:false`, `session.status:"stopped"`, `full_audio:".../full.wav"`.

합격 기준: 조각 누락과 ffmpeg 실패를 명확한 후처리 오류로 반환한다. 결과 파일 존재·유효성을 확인한 뒤 경로를 저장한다. 녹음 종료 시각은 유지하고 합치기만 재시도할 수 있어야 한다. 조각 자체가 유실됐다고 이번 시험으로 주장하지 않는다.

### 3. [P1] 마지막 구간 분석 실패 후 구간 재시도 경로가 사라짐

근거: `lib/facilitator/store.ts`의 advanceFacilitator catch, `lib/live/session.ts:317-352`, `app/api/meetings/[id]/live/stop/route.ts:14-15`.
분석 함수는 실패를 DB에 기록하고 정상 반환한다. stopSession은 run만 failed로 설정하고 session을 stopped로 닫으며 엔진을 제거한다. 종료 API 재호출은 stopped를 보고 즉시 성공 응답하므로 실패 구간을 다시 분석하지 않는다.

합성 재현: 발언 한 개와 종료할 구간을 준비한 뒤 외부 통신 함수가 실패하도록 주입. stopSession은 정상 반환, session은 stopped, run은 failed, facilitator에는 오류가 남았다.

화면의 진행 보조 영역에 실패 경고는 있다. 실패를 완전히 숨긴다고 주장하지 않는다. 수동 전체 분석은 별도로 가능하지만 실패한 시간 구간 재시도를 대체하지 않는다.

합격 기준: 녹음 종료와 분석 완료를 별도 상태로 유지한다. 마이크를 다시 열지 않고 실패한 마지막 구간만 재시도한다. 이미 성공한 구간의 중복 생성·호출을 막고 화면에서 완료·실패 구간을 구분한다.
