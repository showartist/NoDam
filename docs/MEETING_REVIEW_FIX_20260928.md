# 긴 회의 검토 기능 보완 — 2026-09-28

목적: 긴 회의에서 잘못 나뉜 화자를 직접 정정하고, 원음과 전사를 대조하며, AI가 제외한 안건도 근거를 확인하고 다시 질문할 수 있게 한다.

## 1. 화자 일괄 정정
- 원인: 기존 편집기는 발언 한 줄만 수정할 수 있어 수백 개 발언의 화자 정정이 어려웠다.
- 변경: 자동 화자 그룹 여러 개 또는 개별 발언을 선택해 확인한 이름으로 일괄 저장한다. 같은 이름은 같은 화자로 분석한다. 미확인은 자동으로 모두 선택하지 않는다.
- 보호: 원문과 수정 전 기록을 보존한다. 다른 사용자가 먼저 수정했거나 녹음·종료 처리 중이면 전체 저장을 거부한다. 일부 발언만 잘못되어도 나머지를 먼저 저장하지 않는다. 기존 분석은 변경 경고를 표시한다.
- 합격 기준/결과: 부분 선택, 그룹 병합, 원문·감사 이력 보존, 오래된 입력/다른 회의/활성 녹음/다른 출처 요청 차단 테스트 통과. 실제 화면에서 98개 발언 그룹 선택 확인. 실제 참석자의 이름은 임의로 입력하지 않았다.

## 2. 원음 구간 재생과 전사 검토
- 원인: 업로드한 오디오가 전사 작업 폴더에만 있고 화면의 발언과 연결되지 않았다. 공백·경계 구간을 찾으려면 별도 작업이 필요했다.
- 변경: 전사 저장 시 해당 전사 실행과 원음을 함께 연결한다. 회의 화면에 플레이어, 발언별 시간 이동, 우선 확인 구간을 표시한다. HTTP Range로 필요한 바이트를 스트리밍한다.
- 보호: 최신 전사에 연결된 원음만 제공한다. 사용자 입력 파일 경로는 받지 않고 저장된 전사 폴더 밖 파일·심볼릭 링크를 거부한다. 잘못된 범위는 416, 원음 없는 회의는 404다. 기존 팀 접근 제어를 그대로 거친다.
- 검토 기준: 전사 단어 0개인 조각과, 서로 다른 조각의 인접 단어 시간이 200ms 초과로 겹치는 경계를 표시한다. 200ms는 검토 대상을 추리는 운영 기준이지 검증된 오류 판정 임계치가 아니다. 단어는 삭제하지 않는다. 표시되지 않은 부분의 정확성도 보장하지 않는다.
- 실제 자료 검증: 31분 41.88초 녹음에서 공백 조각 3개, 경계 겹침 4개를 연결했다. 434개 발언/1,668개 단어는 변경하지 않았다. DB 백업 후 기존 업로드 파일을 연결했으며 새 전사·외부 API 호출은 없었다.
- 브라우저: ‘1:57 원음 듣기’를 키보드로 실행, 플레이어 currentTime=117.032, paused=false, duration=1901.88 확인. 마우스 자동화 클릭은 반응하지 않아 키보드 경로로 검증했다. 전체 녹음 청취·정답 전사 대조를 수행했다는 의미는 아니다.
- HTTP: 206, Content-Range `bytes 0-1023/5706080`, 응답 1,024바이트가 보관 원음과 정확히 일치. 존재하지 않는 회의는 404.

## 3. AI가 정리됐다고 본 안건 검토
- 원인: 후속 발언에서 정리된 것으로 판정하면 확인 후보에서 빠지고 통계에만 이유가 남았다.
- 변경: 원래 질문·안건 스냅샷을 보존하고 ‘AI가 대화에서 정리됐다고 본 안건’에 이유·근거 발언 링크를 표시한다. 다시 확인 안건으로 가져오면 처음 질문의 근거와 후속 수용 근거가 함께 저장된다.
- 보호: AI 판단은 사람의 승인으로 처리하지 않는다. 최신 완료 분석과 현재 원문이 일치할 때만 가져오며, 중복 가져오기는 안건을 늘리지 않는다. 이전 버전의 ID/이유만 남은 기록은 열람만 가능하다.
- 검증: 합성 모델 응답/DB로 후속 근거 보존, 재질문, 승인·참가자 자동 생성 없음, 중복 방지, 원문 수정 시 차단을 확인했다. 실제 회의 재분석 결과가 아니라 기능 검증이다. 실제 전사 재전송은 이전 자동 승인 검토에서 거절되어 이번 작업에서도 실행하지 않았다.

- 로컬 3212 앱 재시작 완료. 현재 긴 회의 화면에 원음 연결 및 검토 도구 적용.
